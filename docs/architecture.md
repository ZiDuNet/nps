# 系统架构

NPS 由服务端 `nps`、内网客户端 `npc` 和可选的 NPC GUI 组成。服务端负责公网监听、认证、隧道调度和 Web 管理；客户端负责连接服务端并访问内网目标。

## 组件关系

```text
公网访问者
    |
    +--> NPS Web 管理面板 :8081
    +--> NPS 代理入口      :80/:443/隧道端口
                              |
                         Bridge :8024/:8025
                              |
                         NPC 内网客户端
                              |
                         内网目标服务
```

## Bridge 连接类型

客户端建立 Bridge 连接后，先发送版本和 `VerifyKey` 完成认证，再按连接类型进入对应的数据通道：

| 类型 | 用途 |
| --- | --- |
| `main` | 控制连接、心跳、UDP 协商、客户端局域网地址上报 |
| `chan` | 普通 TCP/UDP/HTTP/SOCKS5 数据通道，使用多路复用 |
| `conf` | 客户端配置交换和状态查询 |
| `rgst` | 注册或探测客户端地址 |
| `sert` | Secret 私密代理连接 |
| `file` | 文件访问通道 |
| `p2pm` | P2P 中继和 NAT 协商 |

认证失败、握手超时或协议读取异常时，服务端会主动关闭连接。客户端主连接每 5 秒发送心跳；连接中断后会按重连策略重新建立 Bridge。

## 数据持久化

SQLite 是业务数据的权威存储，默认位于 `conf/nps.db`；`nps.conf` 继续保存进程启动参数：

| 路径 | 内容 |
| --- | --- |
| `nps.conf` | 端口、监听、Bridge、TLS、日志和其他启动参数 |
| `nps.db` | 客户端、用户、隧道、Host、全局参数和运行期业务配置 |
| `nps.db-wal` / `nps.db-shm` | SQLite WAL 及其共享内存索引 |
| `nps.db.lock` | 单进程数据库实例锁 |
| `backups/pre-sqlite-*.tar.gz` | 本次从旧 JSON 启动迁移时，验证过的原始 `conf` 备份 |
| `migration-report.json` | 旧 JSON 导入和收尾报告；全新安装不生成 |

Web 面板修改按实体差异提交；用户或客户端级联删除、全局平台域名与关联 Host 证书更新使用单事务。升级前必须停止服务并备份整个 `conf/`，因为仅复制运行中的 `nps.db` 可能遗漏 WAL。完整迁移、导出、权限和回滚步骤见 [SQLite 数据存储与升级](server/sqlite-storage.md)。

## 请求路径选择

- TCP、UDP、HTTP 正向代理和 SOCKS5：访问服务端为任务分配的公网端口。
- HTTP(S) 域名代理：先将域名解析到服务端，再由 Host 和路径规则选择客户端目标。
- Secret：访问端使用相同密钥启动本地端口，服务端只负责匹配连接。
- P2P：服务端负责协商，实际直连是否成功取决于双方 NAT 类型和防火墙。
- 文件访问：服务端端口映射到客户端本地目录，必须限制目录范围和访问来源。

## 安全边界

Bridge 端口使用 VerifyKey，并对新版 NPC 使用挑战响应认证；Web 管理使用管理员会话或普通用户会话；HTTP/SOCKS5 优先使用混合代理规则级 Basic，未配置时回退到客户端公共 Basic；域名反代优先使用 Host 级认证。公网部署建议：

1. 只开放实际使用的端口。
2. 为管理面板、代理和客户端设置强密码或密钥。
3. 对 Web、Bridge 和代理端口配置防火墙、IP 白名单或反向代理限制。
4. 定期备份 `conf/`，并保护其中的密钥和证书文件。
