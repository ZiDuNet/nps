# NPS 1.1.35 升级说明

本文说明从 1.1.34 或更早版本升级到 1.1.35 时的兼容边界。1.1.35 修复普通用户访问 API 接入页时页面白屏的问题，并补充 README 界面截图，不改变持久化格式、Bridge 协议、`nps.conf` 或现有接口。

## 本版本变化

- 修复普通用户访问 `/user/api` 时被管理员权限守卫误拦截、页面白屏的问题。
- 普通用户现在可以打开 API 接入页，并生成、再次查看或撤销自己的 API Token。
- 用户管理、全局参数和管理员 API 密钥接口仍仅限管理员访问。
- 新增普通用户页面访问与动作白名单回归测试，覆盖允许访问的 API 接入页和个人凭据操作，以及必须继续拒绝的页面。
- README 中英文首页新增登录页、IP 登记页、客户端编辑页和域名反代编辑页截图。

## 兼容性

- 无新增或变更的 `nps.conf` 字段，无配置迁移。
- 无数据库或 JSON 数据格式变更；现有 `clients.json`、`users.json`、`tasks.json`、`hosts.json` 和 `global.json` 可直接使用。
- Bridge 协议、客户端版本分流规则、旧版 Web 接口和 `/api/v1` 行为均不变。
- 管理员权限和普通用户资源隔离规则不变，NPS 与 NPC 不需要同步升级。

## 二进制部署

1. 按既有流程备份 `conf` 目录。
2. 停止 NPS，替换 `nps` 二进制后重新启动。
3. 强制刷新管理面板，以加载本次构建的静态资源。

## Docker 部署

```bash
docker pull wushuo98/nps:1.1.35
docker compose up -d
docker logs nps --tail=100
```

也可以继续使用 `wushuo98/nps:latest`，但生产环境建议固定版本号，升级时明确执行 `docker pull` 并重建容器。

## 验证与回滚

推荐验证：

- 使用普通用户登录并打开「系统 → API 接入」，页面应正常显示，不再白屏。
- 普通用户应能生成、再次查看和撤销自己的 API Token。
- 普通用户访问 `/user/list`、`/global/index` 或管理员 API 密钥接口时仍应被拒绝。
- 管理员访问「系统 → API 接入」和用户管理页面应保持正常。

如需回滚，恢复 1.1.34 二进制和备份配置即可。1.1.35 没有修改持久化数据，旧版本不会因数据格式无法读取而受影响。
