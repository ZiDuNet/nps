# NPS 1.1.40 本地升级说明

> 本文对应运行时资源 ID、实时列表排序和统一分页优化版本。
> 正式发布状态以 `lib/version.VERSION`、GitHub Release 标签和发布流水线结果为准。

## 功能变化

- NPC 配置创建的运行时客户端、隧道和域名反代使用独立临时 ID，不再消耗持久化 JSON 的自增序列。
- 同一客户端的多个运行时 Host/隧道可以并行存在，不会因为临时 ID 或归属判断冲突而互相覆盖。
- 客户端、隧道、域名反代和用户列表支持按实时上行/下行带宽及连接指标排序。
- 所有列表统一提供 20、50、100、200 条每页选项，并保留当前浏览器的分页选择。

## 配置与数据迁移

本版本不新增必填配置，不改变 `nps.conf`、客户端配置或 JSON 数据字段，也不要求迁移现有 `conf` 目录。运行时临时 ID 只存在于内存生命周期中，不会写入持久化资源文件。

升级时仍建议先备份整个 `conf` 目录，尤其是 `clients.json`、`tasks.json`、`hosts.json`、`users.json`、证书和日志文件。

## 升级步骤

1. 备份整个 `conf` 目录。
2. 停止 NPS。
3. 替换 NPS 程序并保留原 `conf` 目录。
4. 启动 NPS 并登录管理面板。
5. 检查客户端、用户、TCP/UDP 隧道和域名反代列表的分页与实时指标排序。
6. 浏览器如保留旧静态资源，强制刷新一次页面。

## 版本兼容

| 组件 | 兼容范围 |
|------|----------|
| NPS `1.1.40` + 旧版 NPC | 继续兼容既有 Bridge 握手、快捷命令和配置文件 |
| NPS `1.1.40` + NPC `1.1.28` 及以下 | 继续使用历史 Bridge 握手和既有 TCP/KCP 连接方式 |
| Web 与 `/api/v1` | 既有路径、字段和响应信封不变 |

本版本的能力集中在服务端运行时资源管理和 Web 列表交互，不强制要求同步升级 NPC，也不会主动断开已有客户端连接。

## 回滚

停止 NPS，替换回 `1.1.39` 程序即可。本版本不修改配置格式和持久化数据结构，通常无需恢复数据；回滚前仍建议保留当前 `conf` 备份。
