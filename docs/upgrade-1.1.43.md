# NPS 1.1.43 升级说明

本版包含移动端认证页面、客户端列表及选择框、IP 归属地、账户管理优化，
以及上版发布后提交的 NPC 更新与重启恢复修复。正式版本以 GitHub Release
及其 `checksums.txt` 为准。

## 主要变化

- 登录、注册、IP 登记页使用紧凑手机布局，支持整页滚动、横屏和安全区。
  邮箱验证、图片验证码、TOTP、PoW、三天免登录及原桌面磨砂双栏均保留。
- 新建、编辑隧道和域名规则的客户端选择框显示备注、ID、所属用户及在线气泡；
  编辑页加载失败或缺少原客户端时，不会自动改绑。
- 客户端列表合并双向累计流量，保留与累计流量分开的双向实时带宽；
  客户端名称可直接修改，数字 ID 和 VKey 不变。
- 浏览器查询公网出口的中文省市区并展示本地国家旗帜。ip258 主接口失败后
  使用 GeoJS 备用，内网不外查。第三方服务可能受网络或 CORS 策略影响，
  查询失败只显示地域未知，不影响穿透。具体城市不保证与设备真实位置一致。
- 完善 NPC CLI、GUI、系统服务升级后的替换、权限保持、重启、连接恢复和回滚；
  服务端将升级触发、执行结果和新版本重新上线确认分开记录。

## 配置与兼容

不需要修改 `nps.conf` 或迁移已有账号、JSON 业务数据、证书、Token 和免登设备。
旧 NPC、快捷命令及既有 API 请求继续可用；普通用户只能选择自己有权访问的客户端。
本版浏览器展示优化不改变流量计量、用户限速或穿透数据链路。

IP 归属地查询由浏览器直接访问第三方服务，不会携带 NPS Cookie、凭据或页面
Referrer；第三方会看到被查询的公网 IP。NPS 不代理查询或持久化结果，浏览器
本地缓存主接口结果 30 天、备用结果 1 天，查询失败后当前页面短暂退避。

## 升级步骤

1. 备份整个 `conf`，包括证书、`instance.key`、`web_sessions.json` 和业务数据。
2. 停止 NPS，替换新服务端程序并保留配置目录，再启动服务。
3. 浏览器强制刷新，检查客户端流量、选择框和手机三种认证页面。
4. 对需要更新修复的 NPC，按 [客户端更新与远程升级](client-update.md) 升级。
   不必为本版的服务端界面改动强制升级全部 NPC。

旧 NPC 实际执行的是其自身携带的旧更新器，单独升级服务端不能让旧进程获得
新重启和恢复逻辑。若首次远程更新失败或无法自动重启，请按对应平台手动替换、
重启或重新安装一次；容器和无写权限的安装仍按容器/系统服务部署方式更新，
不要依赖容器内覆盖二进制。GUI 与系统服务的使用方式详见更新文档。

升级和重新启动 NPC 会中断该实例当前承载的连接，请安排维护窗口。

## 验收与回滚

- 核对面板与 NPC 的产品版本，关注服务端重新上线确认，不以“已触发升级”
  作为成功依据；必要时检查系统服务实际可执行文件路径。
- 手机检查登录、注册和 IP 登记完整可达；按实际配置检查验证码、邮箱、
  TOTP、PoW 及免登录选项，桌面仍保持双栏。
- 若需回滚，停止对应进程，恢复上一正式版本程序和部署方式；本版不要求
  业务数据迁移。保留完整备份，不删除 `instance.key` 或免登设备文件。
