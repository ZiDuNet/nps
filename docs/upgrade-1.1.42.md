# NPS 1.1.42 本地升级说明

> 本文对应账户安全、3 天免登、登录 PoW 和全局页面布局修复版本。
> 正式发布状态以 `lib/version/version.go`、GitHub Release 标签和发布流水线结果为准。

## 功能变化

- 「系统 → 账户管理」统一提供普通用户 API Token、管理员 API 密钥、管理员 TOTP、
  当前账号的登录设备和 3 天免登凭证。
- 勾选“3 天内免登录”后，服务端会在 `conf/web_sessions.json` 登记设备。可查看
  浏览器、系统、IP、创建时间、最近活动时间和到期时间，并单独撤销设备或退出
  所有设备。
- 管理员可在页面中直接绑定、替换或关闭 TOTP，无需运行 `nps -gen2fa` 或重启。
  凭据变更后立即生效，并使旧管理员网页会话失效。
- 「系统 → 全局参数」新增第五个「安全」Tab，集中维护登录 PoW。PoW 只在支持
  Web Worker 的浏览器中计算，不影响 API Token、API 签名、IP 登记或有效的 3 天
  免登会话。
- 原「API 接入」菜单统一更名为「账户管理」；所有页面标题、状态气泡和说明统一
  进入固定顶栏，页面专属操作按钮只保留在内容区一次，顶栏与内容之间保留稳定间距。
- TCP 隧道现在始终维护活动连接数。此前 `MaxConn=0`（不限连接数）不会累加计数，
  因此列表和资源拓扑中的“当前连接”会固定显示为 0；升级后无需修改配置。

## 配置变化

本版本不要求修改现有 `nps.conf`。相关字段仍由服务端配置管理：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `force_pow` | `false` | 是否要求交互式网页登录完成 PoW |
| `pow_bits` | `20` | PoW 难度，页面允许设置为 8-28 |
| `totp_secret` | 空 | 管理员 TOTP 密钥；建议通过账户管理页面维护 |

首次签发 3 天免登 Cookie 时会自动创建 `conf/web_sessions.json`，权限为 `0600`。
该文件不存在时会按需创建；文件无法读取、格式损坏或版本不受支持时会拒绝恢复
免登并回退到正常密码登录，不会放宽校验。

## 数据与备份

- 继续使用现有 `clients.json`、`tasks.json`、`hosts.json`、`users.json` 和
  `global.json`，不改变 JSON 字段。
- 备份 `conf` 时应包含 `web_sessions.json`。删除该文件会让所有已签发免登 Cookie
  失效，但不会删除账号或导致密码登录失败。
- `instance.key` 仍是免登 Cookie 的签名基础，不要在不接受会话失效的情况下删除。

## 升级步骤

1. 备份整个 `conf` 目录。
2. 停止 NPS；NPC 无需因本版本同步升级。
3. 替换 NPS 程序并保留原 `conf`。
4. 启动 NPS，使用管理员账号登录。
5. 打开「系统 → 账户管理」，检查 API 凭据、TOTP、登录设备和免登凭证。
6. 打开「系统 → 全局参数 → 安全」，按需启用 PoW 并保存。
7. 浏览器保留旧静态资源时强制刷新一次。

## 版本兼容

| 组件 | 兼容范围 |
| --- | --- |
| NPS `1.1.42` + 旧版 NPC | Bridge 握手、快捷命令和控制消息保持兼容 |
| 旧 `nps.conf` | 不需要迁移；PoW 和 TOTP 字段继续使用安全默认值 |
| `/api/v1` | 原有路径、字段和响应信封不变 |
| 普通用户账号 | 原有账号密码、客户端 VKey 兼容登录和 API Token 继续有效 |

3 天免登只保存服务端登记和受签名保护的设备 ID，不在 Cookie 中写入密码或 VKey。
未勾选免登的普通登录仍按原有会话生命周期工作。

## 回滚

停止服务并替换回 `1.1.41` 即可。旧版本会忽略 `conf/web_sessions.json`，可以保留
该文件用于以后再次升级，也可以删除以清空残留设备登记。回滚不会修改现有业务
JSON 数据。
