# NPS 1.1.34 升级说明

本文说明从 1.1.33 或更早版本升级到 1.1.34 时的兼容边界。1.1.34 只调整管理面板的列表、表单与详情排版，并修复域名反代表单的一个前端校验问题，不改变持久化格式、Bridge 协议和现有 Web 管理接口。

## 本版本变化

- 域名反代列表移除「认证」列，改为在访问入口前显示 Basic 认证锁图标：规则级或客户端级任一配置了 Basic 认证即点亮；列表数据只返回「是否已配置」，不回传用户名和密码。
- 域名反代与 TCP 隧道列表的展开详情统一为紧凑卡片布局，按业务分组展示；IP 名单以标签呈现，Basic 密码只显示「已设置 / 未设置」。
- 全局参数「平台泛域名」输入区改为单列排版并限制输入框宽度，证书路径、证书状态与到期信息不再拥挤。
- 修复域名反代新增/编辑页在健康检查目标为空时，保存会被浏览器「无效表单控件」校验拦截的问题。

## 兼容性

- 无新增或变更的 `nps.conf` 字段，无配置迁移。
- 无数据库或 JSON 数据格式变更；现有 `clients.json`、`users.json`、`tasks.json`、`hosts.json` 和 `global.json` 可直接使用。
- Bridge 协议、客户端版本分流规则和 `/api/v1` 行为均不变，NPS 与 NPC 不需要同步升级。

## 二进制部署

1. 按既有流程备份 `conf` 目录。
2. 停止 NPS，替换 `nps` 二进制后重新启动。
3. 刷新管理面板（建议强制刷新以加载新的静态资源），检查域名反代列表、展开详情和「全局参数 → 平台泛域名」的排版。

## Docker 部署

```bash
docker pull wushuo98/nps:1.1.34
docker compose up -d
docker logs nps --tail=100
```

也可以继续使用 `wushuo98/nps:latest`，但生产环境建议固定版本号，升级时明确执行 `docker pull` 并重建容器。

## 验证与回滚

推荐验证：

- 域名反代列表中，配置了规则级或客户端级 Basic 认证的条目在访问入口前显示锁图标，表格中不再出现「认证」列。
- 展开域名反代和 TCP 隧道的任意一行，详情以分组卡片显示，无控制台报错。
- 打开「全局参数 → 平台泛域名」，输入框单列显示且宽度收敛，证书信息不重叠。
- 在域名反代编辑页留空健康检查目标并保存，不再被浏览器表单校验拦截。

如需回滚，恢复 1.1.33 二进制和备份配置即可。1.1.34 没有修改持久化数据，旧版本不会因数据格式无法读取而受影响。
