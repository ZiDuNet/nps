# NPS 1.1.33 升级说明

本文说明从 1.1.32 或更早版本升级到 1.1.33 时的兼容边界。1.1.33 主要改进删除客户端后的断连行为与 NPC 数据通道关闭可靠性，不改变持久化格式和现有 Web 管理接口。

## 本版本变化

- 管理面板删除客户端时，NPS 会在断开前向在线的 NPC 下发「注册已删除」指令；新版 NPC 收到后关闭该客户端的控制连接与数据通道，并停止针对该 vkey 的重连，不再每 5 秒空转重试。
- NPC 作为系统服务运行时收到删除指令，只停止被删除的那条连接；当该服务进程内的最后一条连接也因删除而结束时，才自动停止本机 NPC 服务，但保留服务注册，不卸载。同一进程同时连接多个服务端或多个 vkey 时，删除其一不影响其他连接。停止是后台尽力而为的动作，失败也不会阻塞 Web 端删除。
- 修复 NPC 数据通道（MUX）关闭时把 socket 切到阻塞模式，导致连接无法真正断开、文件描述符泄漏的问题；删除客户端后数据通道会立即完整释放。
- NPS/NPC Docker 镜像补齐 CA 证书，修复 Geo 数据在线更新与版本检测报 `x509: certificate signed by unknown authority` 的问题。
- 「API 接入」页面的文档链接改为官方文档站 `https://zidunet.github.io/nps/api.html`，并修复管理员生成密钥按钮请求错误路径的问题。
- 登录页、管理面板主布局和错误页统一显示浏览器标签页图标（favicon）。

## 兼容性

- 无新增 `nps.conf` 字段，无配置迁移。
- 无数据库或 JSON 数据格式变更；现有 `clients.json`、`users.json`、`tasks.json`、`hosts.json` 和 `global.json` 可直接使用。
- 删除指令只被新版 NPC 识别，旧版 NPC 忽略该指令并保持原有重连行为，NPS 与 NPC 不需要同步升级。
- 停用、到期和用户禁用仍使用普通断开方式，NPC 在状态恢复后可以继续自动重连；仅「删除客户端」会下发停止重连指令。
- 旧 `/auth/*`、`/client/*`、`/index/*`、`/user/*`、`/global/*` 的路径、参数和返回格式保持不变，`/api/v1` 行为与 1.1.32 一致。

## 二进制部署

1. 按既有流程备份 `conf` 目录。
2. 停止 NPS，替换 `nps` 二进制后重新启动。
3. 在管理面板删除一个在线客户端，确认旧版 NPC 仍按原方式重连、新版 NPC 停止该连接的重试，且同一进程中的其他 vkey 连接不受影响。

无需修改现有配置文件。若希望删除后立即停止重连，请同时把对应 NPC 升级到 1.1.33。

## Docker 部署

```bash
docker pull wushuo98/nps:1.1.33
docker compose up -d
docker logs nps --tail=100
```

也可以继续使用 `wushuo98/nps:latest`，但生产环境建议固定版本号，升级时明确执行 `docker pull` 并重建容器。

## 验证与回滚

推荐验证：

- 删除一个在线客户端后，Web 响应立即返回；观察 NPC 日志确认收到删除指令并停止该 vkey 的重连。
- 在同一个 NPC 进程中注册两个 vkey，删除其中一个，确认另一个仍在线。
- 系统服务模式下删除进程内最后一个 vkey，确认 NPC 服务被停止但注册保留，之后仍可用 `npc` 命令启动或停止。
- 重启 NPS 后执行一次 Geo 数据在线更新与版本检测，确认不再出现证书校验失败。

如需回滚，恢复 1.1.32 二进制和备份配置即可。1.1.33 没有修改持久化数据，旧版本不会因数据格式无法读取而受影响。
