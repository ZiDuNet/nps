# NPS 1.1.38 本地升级说明

> 本文对应列表交互、连接审计和配置保存修复版本。正式发布状态以
> `lib/version.VERSION`、GitHub Release 标签和发布流水线结果为准。

## 功能变化

- 所有列表页统一使用左侧业务操作、右侧「搜索、筛选、列、刷新」的工具栏，
  修复较窄桌面宽度下刷新按钮换行。
- 客户端、用户、域名反代、TCP 隧道、审计、登录封禁和 IP 登记使用同一套
  列表布局与交互。
- 登录封禁支持关键词搜索、封禁类型和状态筛选及分页。
- 客户端连接日志补充 Bridge 主连接、子通道、握手和认证失败、代理会话的
  服务端地址、公网来源、客户端公网/内网地址来源、版本、通道、阶段、状态
  和到期信息。
- 管理操作审计和连接日志的展开详情使用终端式原始 JSON 视图，便于复制和
  排查，同时保持紧凑高度。
- 服务端配置分类保存只校验当前页面负责的字段，避免证书设置、用户注册或
  SMTP 配置阻塞通用配置页保存；配置卡片改为 3/4 列响应式网格。

## 配置与数据迁移

本版本不新增必填配置，不改变 `nps.conf` 字段语义，也不需要迁移 JSON 数据。
升级时保留现有 `nps.conf`、`clients.json`、`tasks.json`、`hosts.json`、
`users.json`、证书和日志文件。

## 升级步骤

1. 备份整个 `conf` 目录。
2. 停止 NPS。
3. 替换 NPS 程序并保留原 `conf` 目录。
4. 启动 NPS，登录管理面板。
5. 抽查客户端、用户、域名反代、TCP 隧道、审计与连接、登录封禁和 IP 登记
   页面，确认工具栏顺序、筛选、列显示和刷新正常。
6. 打开「审计与连接」，确认展开详情可显示完整字段和原始 JSON。
7. 打开「系统 → 全局参数」，分别保存通用配置、用户注册和证书设置中的
   可修改项，确认专项页配置不会阻塞其他页面。

## 版本兼容

| 组件 | 兼容范围 |
|------|----------|
| NPS `1.1.38` + NPC `1.1.37` | 完全兼容 |
| NPS `1.1.38` + NPC `1.1.28` 及以下 | 继续使用历史 Bridge 握手和既有 TCP/KCP 连接方式 |
| 快捷命令 | v1/v2 格式均不变 |
| Web 与 `/api/v1` | 既有路径、字段和响应信封不变 |

NPS 与 NPC 不需要同步升级。本版本的新增能力集中在服务端 Web 和审计日志，
不会强制断开已有客户端。

## 回滚

停止 NPS，替换回 `1.1.37` 程序即可。本版本未修改配置格式和持久化结构，
通常无需恢复数据；如果回滚前修改过专项配置，仍建议先备份当前 `conf` 目录。
